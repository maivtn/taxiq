Business Analysis · Version 1.0

Loyalty Points & Reward Redemption

A safe, traceable model connecting Reward configuration, Customer Wallets, POS, cross-location redemption, and immutable audit history.

01 · Business Context

What the system must solve

1

Clear economics

Owners define how points are earned and exactly what each reward costs.

2

Safe redemption

Staff never calculates the deduction. The server validates and deducts atomically.

3

Complete traceability

Every change links customer, actor, location, source, time, and resulting balance.

Phase 1: Cross-location redemption is allowed only between locations owned by the same merchant.
02 · Wallet Model

Pending Points

8,420

04 · Lifecycle

Reward Instrument state model

Atomic and idempotent

Deduction and issuance succeed together. Retries return the original result.

Corrections are additive

Refunds create compensating events. Existing history is never edited or deleted.

08 · Acceptance Criteria

What “done” means

System calculates and deducts points.
Exact before/after balance is confirmed.
Deduction and issuance are atomic.
Every instrument has a unique code/QR.
Double redemption is impossible.
Issued and Redeemed are separate linked events.
Cross-location is merchant-scoped.
Wallet separates all three balances.
Activity supports complete lookup.
Adjustments require role, reason, and audit.
Refunds create compensating events.
Exports respect filters and access scope.
